## 1. 第5章研究问题

第5章研究的是：

- 在全网背景下，预算受限时监测点如何布局
- 不同布局如何影响缺陷定位效果
- 如何提出更有解释力和创新性的布局优化方法

为了保证不同布局方案之间具有可比性，第5章主实验采用统一评估协议。

## 2. 当前统一评估协议

第5章主实验默认保持以下条件一致：

- 候选缺陷节点集合
- 正式缺陷场景集合
- 样本定义与输入口径
- 主模型结构与训练配置

主实验中重点变化的是：

- 监测点布局 `S`
- 布局诱导出的观测节点集合
- 对应的 observed mask / sparse observation pattern

## 3. `C` 与 `S_feasible` 的解释

第5章统一采用下面这套解释：

- `C`
  - 候选缺陷节点集合
  - 是缺陷定位的假设空间
- `S_feasible`
  - 可布设监测点集合
  - 是监测布局的设计空间

因此：

- `C` 不等于监测点只能在候选节点内选
- 第5章不能被解释成“50 个候选点里选 25 个点”的子集问题
- 第5章仍然是一个面向全网的监测布局优化问题，只是用候选缺陷空间上的定位结果来评价布局优劣

当前对这两个集合的进一步判断是：

- `C`
  - 当前总体上是合理的
  - 更适合被表述为“诊断假设空间”
- `S_feasible`
  - 当前更接近图层面的可布设代理集合
  - 在算法研究上可接受
  - 但如果写成强工程可实施集合，仍然偏弱

因此，第5章现阶段默认采用的说法是：

- 当前主实验使用图层面的 `S_feasible` 代理定义
- 后续如需强化工程可实施性，可以再引入更严格的 feasible-set 文件或约束

## 8. 当前默认实验顺序

当前第5章更合理的推进顺序是：

1. 先验证主线解释是否站得住
   - `C` 是否作为缺陷假设空间成立
   - `S_feasible` 是否仍然保持全网监测设计意义
2. 再比较布局基线与任务驱动方法
   - `random`
   - `degree`
   - `betweenness`
   - `downstream`
   - `candidate_observability`
   - `identifiability_driven`
3. 再推进创新方法
   - 两阶段框架法
   - 更强的结构发明型方法
4. 预算实验放在主线站稳之后再展开

当前优先级再明确一层：

1. 先守住 `C` / `S_feasible` 的科学解释
2. 先验证提升是否只是来自更大 `S∩C`
3. 再推进主方法强化
4. 最后再展开完整预算实验
